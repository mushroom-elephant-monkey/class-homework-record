# 班级作业收交情况记录

### 👉 [点这里直接在线试用](https://mushroom-elephant-monkey.github.io/class-homework-record/)

**不用下载、不用安装。** 打开后点任意一个班就能看到界面，点「测试班」随便试，不影响别的班。

> 建议先把页头那个「下次直接进本班」的勾选框**取消**，否则下次打开会直接跳进某个班。

---

一个给班主任和任课老师用的**作业收交记录工具**。
单文件网页，打开就能用；配上服务端，可以扩成一整套全校在线的系统。

默认给了 高一 / 高二 / 高三 各 3 个班，加 1 个测试班，**班号可以自己改**。

---

## ⭐ 特别适合寄宿制学校

### **适用于寄宿制学生：学生或家长没有个人电子设备，这套系统照样能用起来。**

学生不带手机，教室里那块**希沃白板就是现成的入口**。课代表在白板上点完，数据就已经上网了。
**学生一个设备都不用有**，班主任和任课老师用手机随时能看到。

> 很多「在线」的东西默认学生有手机、家长能配合。寄宿制学校这条前提一破，那些方案就全用不上了。
> 而这个工具用的是学校本来就有的那块白板 —— 零新增硬件、零学生设备。

## 一、从记一个班，到管一个学校

最初它只是一个本地单文件网页：双击打开，记自己班的作业。

现在它是一所学校的在线系统——高一到高三**七十多个班**接进来，
其中**二十多个班每天在用**，累计记录了**六百多次作业、三万多条逐人标注**。

同一套界面，同一个链接。老师用手机打开就能记，打开就能看。

从「一个人的工具」到「一个学校的系统」，中间要跨过三件事：

**能改**——把它改成适合自己学校的班级结构；
**能放**——有个地方让它跑起来；
**能发**——别人打开就能用。

这三样具体是怎么解决的，见第三节。

## 二、每天怎么用（5 分钟）

### 早读：登记，约 5 分钟

课代表把作业收齐、点清之后，早读开始时**在教室希沃白板上打开在线网页**，
选科目、选作业项，按小组逐人点：

| 点击次数 | 状态 |
|---|---|
| 点一下 | **已交** |
| 再点一下 | **请假** |
| 第三次 | 回到**未交** |

全班四五十人，把当天的作业全部点完，**5 分钟以内**。
点完即存，不用点保存，不用等同步。

> 📣 **一个实际体会：这件事最好让课代表在班里公开做。**
>
> 早读时当着全班、在希沃白板上点，本身就是一次提醒——"该交作业了"。
> 用下来明显感觉，**公开点比私下记更管用，收作业率会高一些**。
>
> 名字挂在白板上，谁交了、谁没交，全班都看得见。这算一种很朴素的仪式感，
> 但对早读那种松散的气氛，它是有效的。

### 白天：查看，打开就有

班主任、任课老师只需要**用手机或电脑打开自己班的链接**——
当天未交作业的名单就在首页，一眼看完，直接照着催。

不用在群里问、不用等接龙、不用再抄一遍。

### 为什么单独设了「请假」

「请假不计入应交」是三态设计的核心。

病事假和欠交是两回事。混在一起，数据就不可信了——一看到"张三欠交 3 次"，
实际人家请了两次病假，这份名单你就不敢用了。不敢用，前面所有功夫白费。

**这一条决定了工具有没有人真的用起来。**

## 三、联网部署（进阶）

本仓库发布的是**纯前端单文件版本**：零后端、零构建、零依赖，数据存在浏览器 `localStorage`。
适合个人单机使用，也适合当作一个「能直接跑起来的最小实现」来读。

但如果你想让**全校老师一起用**——一个地址、各班数据互不干扰——就得给它补一个后端。
这一步不用你会编程。

### 这一步不用自己写代码

先交代一句：**我不是程序员，这一整套东西是用 WorkBuddy 做出来的。**

联网要解决三件事，它各对应一块：

| 要做什么 | 它怎么帮上忙 |
|---|---|
| **改代码** | 把需求说清楚，它写代码、查 bug、跑测试；你只负责试用和验收 |
| **放服务** | 自带云空间，服务端代码放进去就能跑，不用买服务器、不用配域名 |
| **发布上线** | 一键发布成一个 https 地址，发给老师就能访问 |

下载安装之后，把项目目录交给它，再发一段话说清要什么——就是下面那段。

### 接口约定

**同一套前端代码支持联网多用户部署。** 需要补的只有服务端，接口约定很简单：

| 项 | 约定 |
|---|---|
| 读取 | `GET /api/data?c=<班级ID>` → 返回该班整份 JSON；班级未启用时返回 `null` |
| 保存 | `POST /api/data?c=<班级ID>`，Body 为整份 JSON |
| 落盘 | 每班一个独立文件，如 `data-<班级ID>.json` |
| 健康检查 | `GET /api/health` → 200 即视为服务端可用 |
| 前端行为 | 启动时探测 `/api/health`，通则走服务端，不通则自动退回 `localStorage` |

这种「前端一套、存储可换」的结构，改造量很小：前端只需把 `loadLocal()` / `persist()`
替换成 `fetch` 调用，记录、统计、导出这些业务逻辑一行都不用动。

### 可以直接发给它的一段话

上面那张接口表，其实也是写给 AI 的。把这段话原样发过去：

> 给这个单文件网页加一个后端：实现 `GET/POST /api/data?c=<班级ID>` 读写整份 JSON，
> 每班各存一个 `data-<班级ID>.json`，再加一个 `GET /api/health`。
> 前端启动时探测 `/api/health`，通就走服务端，不通回退 localStorage。

它会写好服务端代码，你放进云空间，点一下发布——
**剩下的部分就是「验收」，不是「编程」。**

接口约定写这么细，就是为了让它一次能接对。

### 实际运行规模

已在真实环境中按此形态运行：一所完全中学 **高一到高三共 76 个班级**接入选班页，
其中 **20 余个班级进入日常使用**，累计记录作业 **600 余次**、逐人标注 **3 万余次**。

教师通过手机或电脑浏览器访问同一地址，选择本班即可查看和记录，各班数据相互隔离。

### ⚠ 为什么仓库里没有服务端代码

**这是故意的。** 学生名单属于未成年人个人信息。一个没有鉴权的
`GET /api/data?c=<班级ID>`，如果班级 ID 可枚举，等于把全校名单敞在公网上。

真要联网部署，至少做到下面几条：

- 班级 ID 不可预测，或接口加鉴权（登录 / Token / 会话）
- 读接口**不要回传**班级密码字段
- 部署在校内网，或用 HTTPS
- 定期导出备份，别把唯一副本只放在服务器上

> 一句话：**单机用这个仓库是安全的；联网用，请自己把鉴权补上。**
> 故意不提供开箱即用的服务端，就是不想让不懂的人随手部署出一个没上锁的接口。

## 四、本地单机使用

**1.** 下载本仓库的 `index.html`

**2.** 双击，用浏览器打开（Chrome / Edge / 新版 Firefox 均可）

**3.** 打开后先**选一个班**

**4.** 进入「设置 → 学生名单（分组）」

> 新班第一次打开时，里面已经放好了 **12 个虚构的示例学生**（3 组，每组 4 人），
> 每个班的名字都不一样，纯粹是为了让你一进去就看到界面长什么样。
> **这些名字都是编的，不对应任何真实学生。**
>
> 换成自己班：在这个框里**直接粘贴**你的名单覆盖掉即可，一行一个 `组号 姓名`：

```
1 张三
1 李四
2 王五
2 赵六
```

> ⚠ **组号和姓名之间必须有空格。**
> 写成 `1张三` 会解析失败——整个班会被塞进第 1 组，而且姓名里还带着数字。这个坑我踩过。

**5.** 到「设置」里改掉默认密码，然后回首页开始记录

> 📌 想先看看长什么样，就点 **「测试班」**，随便点、随便试，不影响其他班。
> 旁边还有个「**便捷名单转换**」，把从别处复制来的名单整理成 `组号 姓名` 格式再粘贴。

## 五、功能

- 三态记录：已交 / 请假 / 未交，**请假不计入应交**
- 按小组逐人点选，支持多科目、多种作业项
- 当日统计、本周汇总、自定义日期范围
- 按科目、按学生两个维度查看
- **未交名单**：一竖列对一次作业，直接照着催
- **一键导出四张 Excel**：已交 √ / 未交 × / 全部 √×假 / 未交名单
- 免密时段：可设定每天某个时段免密码操作，其余时间需要密码

## 六、几件要先说清楚的事

### 1. 法定节假日写死在代码里，每年寒假会更新一版

免密时段判断"今天算不算工作日"时，用到的那张法定节假日表
（`index.html` 里搜 `LEGAL_HOLIDAYS` / `LEGAL_WORKDAYS`）是**内嵌在代码里的，不太好自己改**。

三种处理办法，任选一种：

| 办法 | 说明 |
|---|---|
| **等新版本** | 本仓库通常在**每年寒假**发一版，把当年国务院公布的节假日安排更新进去，到时候换新版本即可 |
| **自己改** | 打开 `index.html` 找到那张表，照着新一年的通知改日期就行（就是一行行日期，不需要懂编程） |
| **干脆不管** | 周末和假期学生基本回家，本来就不会有人去点。系统只是"能点"，不是"必须点"，不影响实际使用 |

> 我个人用的是第三种 —— 那几天没人点，等于没影响。

### 2. 只有面向学生的统计，没有"老师标记"这类功能 —— 这是故意的

**本系统的出发点只有一个：给老师减负担，不是加负担。**

所以它**故意不做**这些：

- 老师对学生的评价、标记、打分
- 教师工作量统计、班级排名评比
- 任何需要老师**额外多录一次**的字段

**希望二次开发的朋友也不要加这类功能。**
一个工具一旦开始要求老师"多点几下、多填几项"，它就会从"帮手"变成"任务"，
最后的结果就是谁都不用了 —— 这是我做这个工具最不想看到的。

### 3. 交作业和成绩有关系，但它不是考核工具

实践里能看出来：**交作业情况和成绩有一定相关性，但更相关的其实是作业质量、学习态度。**
一个每次按时交、但都是抄的学生，和一个偶尔没交、但每次都自己认真做的学生，
在这套记录里是分不出高下的。

**所以本系统不具有对师生的考核功能**，也不建议拿它当任何考核依据。

它只回答一个问题：**今天谁没交。**

## 七、自定义班级

班号写在 `index.html` 里的一段配置中，用记事本打开搜 `CLASS_GROUPS` 就能看到：

```js
function seqClass(prefix, n){ const a=[]; for(let i=1;i<=n;i++) a.push(prefix + String(i).padStart(2,'0')); return a; }

const CLASS_GROUPS = [
  { name:'高一', classes: seqClass('高一', 3) },   // 高一01 – 高一03
  { name:'高二', classes: seqClass('高二', 3) },   // 高二01 – 高二03
  { name:'高三', classes: seqClass('高三', 3) },   // 高三01 – 高三03
  { name:'测试班（随便试，不影响真实班级）', classes: ['测试'], minor:true,
    tools:[ { id:'roster', label:'便捷名单转换' } ] }
];
```

| 想做什么 | 怎么改 |
|---|---|
| 每个年级 6 个班 | 把 `seqClass('高一', 3)` 里的 `3` 改成 `6` |
| 只用一两个年级 | 不需要的那几行整行删掉 |
| 用真实班号 | 不用 `seqClass`，直接写 `classes: ['2024级1班','2024级2班']` |
| 改名 | 改 `name:` 后面那串 |

⚠ **三条要记住：**

1. **班号就是按钮上显示的文字。** 写「高一01」就显示「高一01」，进班后页头自动加「班」字。
2. **班号同时是数据存储的键名**（`hw_checkin_data_v4_<班号>`）。**改班号等于换一份新数据**，原来的数据还在浏览器里，但页面找不到了。
3. 班号一旦开始录数据，**就别再改**。

> 🔴 **不要为了「一个班一个文件」复制多份 `index.html`。**
> 在 `file://` 下，同一浏览器的所有本地 HTML 共用同一份存储——多份文件会互相覆盖，数据必丢。

## 八、⚠ 数据存在哪里（这一节最重要）

**数据保存在你当前浏览器的本地存储里，不上传任何服务器。**

| 情况 | 后果 |
|---|---|
| 换电脑、换浏览器 | 数据不会自动跟过去 |
| 清理浏览器数据 | **数据会丢** |
| 同一个文件用另一个浏览器打开 | 看到的是空白 |

**所以必须定期备份：**

- **备份**：设置 → `导出数据(JSON)` → 存进网盘或 U 盘
- **恢复**：设置 → `导入数据(JSON)` → 选中那个文件 → 数据全部回来

一个班整个学期的数据也就几十 KB，**建议每周导一次**。

## 九、技术说明

- **单文件**：HTML / CSS / JavaScript 全在一个 `index.html` 里，约 2070 行、100 KB
- **零依赖**：不用框架、不用 npm、不用构建，改完刷新即可
- **零后端**：没有服务器、没有 API，不发起任何网络请求
- **可离线**：断网照常使用
- Excel 导出是手写的最小 OOXML + ZIP（store 模式），没有引入任何第三方库

> 想验证"真的不联网"，打开 `index.html` 搜 `fetch` 和 `XMLHttpRequest`——一个都没有。

## 十三、一点背景

这个工具最初是为了解决一个很具体的小事：每天早上清点谁没交作业。

纸质名单点一遍、微信群里问一圈、再抄一张未交名单给课代表——每天十几分钟，
学期末还查不出某个学生到底交过几次。真正麻烦的不是"记录"，是**记完之后要数、要汇总、要回溯**。

所以它只做了三件事：点得快（三态、按组点选）、查得到（按人按科目回溯）、
算得清（四张表直接导出打印）。

如果你也在为同样的事花时间，拿去用就是了。
